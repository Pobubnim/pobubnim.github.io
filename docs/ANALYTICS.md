### Разбивка интерактивов (26.08, analytics.js?v=3)

Каждое действие на доске урока шлёт, кроме цели, ПАРАМЕТРЫ ВИЗИТА
деревом `lesson → доска → контрол` (например `lesson / kolesa-lift-gamma-
gain / колесо:gain`). Что считается:
- кнопки `.vbtn`/`.fbtn` — каждый клик; контрол из data-атрибута
  (`прибор:` view/pview, `кадр:` frame, `задание:` scene, `метод:` method,
  `стадия:` bmode, `кривая:` curve, `кнопка:` сброс/пересыпать/текст);
- колёса и мастер-рейки (`[data-disc]`/`[data-rail]`, pointerdown) —
  `колесо:имя` / `рейка:имя`, один раз за страницу на каждый контрол;
- каждый range-ползунок — `ползунок:имя` (data-param/data-wells/stops/
  exposure/id), один раз за страницу на каждый ползунок (раньше глушился
  ПЕРВЫЙ любой ползунок на страницу — потому «крутил ползунок» почти
  не рос).
Смотреть: Метрика → Отчёты → Содержание → Параметры визитов (дерево
lesson) или блок «Интерактивы» ежедневной сводки. Данные копятся с
деплоя 26.08 вечера.

ВАЖНО: при правке целей/событий поднимать версию `analytics.js?v=N`
во ВСЕХ html разом (39 файлов) — иначе браузеры держат старый скрипт
кэшем и события идут по-старому.

(НЕ в репо! репо публичный). Приложение «Pobubnim Stats Bot»

Shlagerez2535), скоупы: metrika:read + webmaster:verify + webmaster:hostinfo.
Протух токен → oauth.yandex.ru/authorize?response_type=token&client_id=<id>
под рабочим аккаунтом, новый токен в тот же файл.

Сеть на машине падает ВОЛНАМИ по 2–5 минут (TLS-таймауты на любой адрес,
при этом браузер живой; env_doctor чист — это не сокеты). Поэтому скрипт:
ждёт окна сети до 40 минут (проба раз в минуту), затем ретраи 5/20/60/120/180
сек на каждый запрос; HTTP-ошибки (4xx) не ретраятся. Если сеть так и не
поднялась — уходит короткое «не смог собрать, сеть», а не тишина.
Задача планировщика: догоняет пропущенный запуск (ПК был выключен) и
перезапускается до 3 раз с интервалом 30 минут.
