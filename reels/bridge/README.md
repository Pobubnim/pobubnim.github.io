# Мост Claude ↔ ChatGPT: как два агента работают над рилсами

Общей памяти и общего чата у агентов нет. Работа передаётся только через файлы
и ветки этого репозитория. Роли:

| Кто | Что делает | Где пишет |
|---|---|---|
| Claude | сценарии, задания на картинки, голос, сборка роликов, тексты постов | ветка `claude/blog-setup-chatgpt-images-8jobkr` (дальше — рабочая ветка рилсов) |
| ChatGPT | рисует картинки по заданиям | ветка `codex/reels-images`, только папка `reels/incoming/` |
| Владелец | передаёт сигнал «готово» и принимает ролики | чат с любым из агентов |

## Цикл одного ролика

1. **Claude** пишет сценарий `reels/scripts/<slug>.json` и командой
   `python reels/reel.py task <slug>` выпускает задание `reels/bridge/tasks/<slug>.md`:
   по промпту на кадр и имя файла.
2. **ChatGPT** берёт задание с рабочей ветки рилсов, рисует кадры и кладёт их в
   `reels/incoming/<slug>/s1.jpg … s5.jpg` на ветке `codex/reels-images`
   (ветку создать от рабочей ветки рилсов). Затем отмечает задание в
   `reels/bridge/STATUS.md` и пушит ветку. Если у ChatGPT нет записи в GitHub,
   владелец скачивает картинки из чата и загружает их в ту же папку через сайт GitHub
   (Add file → Upload files, ветка `codex/reels-images`).
3. **Claude** забирает ветку (`git fetch origin codex/reels-images`), переносит
   картинки из `reels/incoming/` и собирает ролик: `images` берёт присланные кадры
   первыми, API не вызывает. Готовый mp4, обложка и тексты уходят владельцу.
4. Кадр не подошёл → Claude пишет в `STATUS.md` строку «переделать s3: причина»,
   ChatGPT перерисовывает только его.

## Правила, чтобы не мешать друг другу

- ChatGPT не трогает ничего вне `reels/incoming/` и `reels/bridge/STATUS.md`.
  Сценарии, код и задания меняет только Claude.
- Имена файлов строго из задания: `s1.jpg`, `s2.jpg`… Другой формат (png, webp)
  тоже примется, размер подгоняется сам (обрезка по центру до 2:3).
- Один файл до 1,5 МБ. Тяжёлые исходники в git не класть.
- В кадре нет текста, логотипов и узнаваемых лиц: титры ставит сборка.
